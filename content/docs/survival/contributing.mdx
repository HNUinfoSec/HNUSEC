title: 一起写生存指南
description: 从一个你亲自遇到过的问题写起。
---

你不需要先有一篇完整的“大学四年攻略”。一次选课经历、一份课程实验的环境记录，或者刚入学时走过的一段弯路，都可以成为这份指南的一部分。

## 怎样的文章适合放在这里

尽量写清楚自己遇到了什么问题、试过哪些办法、最后怎样解决，以及还有什么没弄明白。

- 写亲身经历，说明当时的年级、课程、学期或设备环境。
- 涉及学校规定时，附上对应通知的链接和适用年份。
- 推荐工具或服务时，交代你用它完成了什么，以及是否需要付费。
- 保留个人表达，也允许不同同学有不同的体验。

如果只是有个选题，还没想好怎么写，可以先[开一个 Issue](https://github.com/HNUinfoSec/HNUSEC/issues/new)，写下问题和你已有的材料。

## 文章从哪里开始写

在 `content/docs/survival/` 下新增一个 MDX 文件，文件名使用小写字母和连字符，例如 `my-first-lab.mdx`。可以参考下面的结构，按自己的内容增删段落：

````mdx
---
title: 我的第一份课程实验环境记录
description: 一句话介绍这篇文章能帮同学解决什么问题。
---

作者：你的名字

适用范围：课程、年级或设备环境

最后核实：YYYY-MM-DD

## 当时遇到了什么

写下具体问题和必要的背景。

## 我是怎样处理的

记录有效的步骤，也可以讲讲走过的弯路。

## 给后来同学的提醒

哪些条件可能和你当时不同？还有哪些问题没有解决？
````

然后把文件名（不含 `.mdx`）加入同目录的 `meta.json`，保留已有条目。例如：

```json
{
  "title": "HNU 生存指南",
  "pages": ["index", "contributing", "my-first-lab"]
}
```

新增文章后，也可以在指南首页的“已经可以读的内容”中添加入口，让读者容易找到。

Fork、安装依赖、本地预览和提交 Pull Request 的步骤见[仓库 README](https://github.com/HNUinfoSec/HNUSEC#如何提交文章)。

## 署名与后续更新

文章保留作者署名。整理指南时，我们会调整目录、增加导读和文章入口，已有的署名正文由作者维护。

发现过时信息或有不同经验时，先在 Issue 里记录问题，或另写一篇补充文章；需要修改原文时，联系作者确认。转引其他人的材料时，请附来源，不要直接搬运整篇文章。
